# ATL v0.4.5 — Adaptive Operator Engine

Adds bounded arithmetic sequences and input-only operator selection on top of v0.4.4 repeats. This is a conventional lossless coding technique, not a novel compression algorithm.

## Syntax
`D:10*4,12:3:4,20:-2:3` expands to 10,10,10,10,12,15,18,21,20,18,16. The final line is FINAL: 16. A repetition count is the total number of occurrences (at least two). Arithmetic syntax is start:signed_nonzero_step:count, count at least three. Expansion is bounded by the known task length (at most 200). The compact-language control uses DP: and equivalent vxk and v/step/k syntax. Dense uses only a comma-separated list. No executable arbitrary code.

The reference encoder uses dynamic programming to choose literal, repeat and arithmetic-run chunks; exact minimum character cost within the grammar (token-chunk cost is approximate at boundaries). The decoder validates syntax, ranges and expanded length; the verifier independently checks every state and the final answer.

## Data and routing
320 new synthetic instances, 80 per profile: interval-overlap, interval-chain, inventory-steady, inventory-variable. Two families, 60–180 states each. 80 development, 240 pilot. The bounded inventory task clamps signed daily changes to [0,capacity]. The interval task checks weighted nonoverlapping prefix optima. Independent alternative algorithms check all states. Cases are generated by an authored generator, not blinded/external.

The router uses only observable input features: adjacent job overlap fraction or repeated adjacent inventory deltas, threshold 0.5. It learns the least total static cost per feature bin on development cases only, separately for both language arms. It never solves a pilot task to pick its mode. Character-trained router chooses RLE for interval overlap, sequence for interval chain and steady inventory, dense for variable inventory. This is a simple heuristic and might not generalize beyond the four engineered profiles.

## Executed software checks
320/320 reference and alternative algorithm agreements for every state, 1600/1600 fixed-mode lossless roundtrips and certificates, 4807 invalid variants rejected, 10 empty-vector checks and 5 decreasing-progression checks. Executed in JavaScript during development; CLI and provider integration not executed here.

No LLM efficiency or token savings claim follows from these results.

## Reproduction
From repo root, Node 18+:
```sh
node operator_engine/static.mjs
node operator_engine/static.mjs /path/to/o200k_base.tiktoken
node operator_engine/run.mjs --model YOUR_MODEL
mkdir -p results
node operator_engine/run.mjs --execute --model YOUR_MODEL --out results/operator-engine-run
```
Static tokenizer mode uses the existing independent rank-based tokenizer and trains the router for that counting function. The live runner freezes the character-trained router, so its selection can differ from a token-trained router. The rank file and tiktoken package were not available in this environment; actual token counts and independent inference are pending. See adaptive/README.md and reasoning/README.md for tokenizer and provider configuration. Full run requests 1680 independent completions per trial, no automatic retries. Primary comparison compact-adaptive vs atl-adaptive, secondary dense vs atl-adaptive; use provider-reported usage, including failed certificates when usage is known, and report coverage.
